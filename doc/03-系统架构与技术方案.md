# 基于 TimeMixer 的水厂流量预测及可视化分析系统架构与技术方案

## 1. 架构设计目标

系统架构设计需要同时满足以下目标：

- 支持业务系统与算法模块解耦
- 支持数据管理、模型训练、预测分析、可视化展示的完整链路
- 便于后续扩展更多模型、更多数据指标与更多展示方式
- 适合毕业设计答辩时清晰讲解系统组成与模块职责

## 2. 总体架构

建议采用四层架构：

- 表现层：Vue 3 前端、大屏页面、Three.js 三维场景
- 业务层：Spring Boot 提供统一接口、权限、任务编排、数据聚合
- 算法层：Python 实现 TimeMixer 训练与预测服务
- 数据层：PostgreSQL 存储业务数据、任务数据、结果数据

可抽象为如下逻辑：

1. 前端发起数据管理、训练、预测、查询请求
2. Spring Boot 接收请求并执行业务校验
3. 与 PostgreSQL 交互，读取原始数据、保存任务信息与结果摘要
4. 调用 Python 算法服务执行训练或预测
5. Python 返回任务结果、指标结果、文件地址或预测结果
6. Spring Boot 整理数据后返回前端
7. 前端将结果以图表、大屏和三维场景进行展示

## 3.2 后端模块

后端目录建议位于 `/project/server`，建议按经典分层拆分：

- `controller`：接收前端请求
- `service`：业务逻辑实现

- `dto` / `vo`：接口请求与响应对象
- `config`：安全、跨域、序列化、线程池配置
- `job` 或 `task`：异步任务处理
- `client`：Python 算法服务调用封装
- `common`：统一返回结构、异常处理、工具类

## 3.3 算法模块

算法代码建议单独维护，逻辑上与 Spring Boot 解耦。

建议模块划分：

- `data_loader`：数据读取与样本构建
- `preprocess`：缺失值、异常值、归一化处理
- `models`：TimeMixer 模型实现
- `train`：训练脚本
- `predict`：预测脚本
- `evaluate`：指标评估
- `api`：算法服务接口封装
- `outputs`：模型文件、指标文件、预测文件输出

### 算法服务建议能力

- 健康检查接口
- 启动训练接口
- 查询训练状态接口
- 执行预测接口
- 获取指标结果接口

## 4. 系统协同方案

## 4.1 推荐协同模式

推荐使用“Spring Boot + Python HTTP 服务”的方式。

其优点包括：

- 业务层与算法层职责清晰
- 接口调用简单，便于联调
- 易于在论文中描述系统架构
- 适合后期替换模型实现

## 4.2 训练流程设计

建议训练流程如下：

1. 前端提交训练配置
2. Spring Boot 保存训练任务记录，生成任务编号
3. Spring Boot 调用 Python 训练接口
4. Python 加载数据、执行训练、保存模型文件
5. Python 返回训练结果、指标与文件信息
6. Spring Boot 更新任务状态并保存模型版本
7. 前端轮询或查询任务详情展示训练进度与结果

## 4.3 预测流程设计

建议预测流程如下：

1. 前端选择模型版本与预测范围
2. Spring Boot 校验参数并生成预测任务
3. 调用 Python 预测接口
4. Python 输出未来预测结果与误差结果
5. Spring Boot 保存预测结果并生成可视化摘要
6. 前端展示预测曲线、结果表格、误差分析图

## 9. 关键设计决策建议

### 9.1 为什么业务与算法分离

- Java 更适合权限、任务、接口、系统化业务实现
- Python 更适合模型训练与实验代码
- 分离后便于单独调试算法与平台

### 9.2 为什么使用 PostgreSQL

- 支持结构化业务数据
- 支持较强的查询能力
- 适合保存预测结果、任务记录、统计汇总数据

### 9.3 为什么需要 Three.js

- 增强作品展示亮点
- 将抽象的流量数据映射到直观场景
- 提升答辩时的视觉表达力

## 11. 风险与预案

### 11.1 数据量不足

- 预案：构造演示数据集并结合真实样例进行补充

### 11.2 模型效果不稳定

- 预案：保留多组参数实验结果，必要时增加对比模型

### 11.3 前后端联调复杂

- 预案：先定义接口契约和 mock 数据，再逐步替换真实接口

### 11.4 三维场景开发工作量大

- 预案：采用简化场景模型，不追求复杂建模，重点突出联动效果
